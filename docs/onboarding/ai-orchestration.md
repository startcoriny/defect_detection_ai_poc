# AI Orchestration Guide

## 목적

AI Agent 간 역할을 명확하게 분리하여 설계, 구현, 검증 과정을 효율적으로 수행합니다.

역할을 분리함으로써 작업 중복을 줄이고 각 Agent의 강점을 활용하여 개발 생산성을 높입니다.

---

## Agent 역할

### CLAUDE

CLAUDE는 설계와 문서화를 담당합니다.

주요 역할

- 요구사항 분석
- 기능 명세 작성
- 아키텍처 설계
- 데이터 모델 설계
- API 설계
- 기술 의사결정 문서 작성
- 구현 가이드 작성
- 코드 리뷰
- Work Log 작성
- PR 초안 작성

CLAUDE는 구현보다 설계와 검증에 집중합니다.

세부 규칙은 `CLAUDE.md`의 AI 역할 분리 규칙 / 구현 지시서 작성 규칙을 참조합니다.

---

### CODEX

CODEX는 구현을 담당합니다.

주요 역할

- 기능 구현
- 테스트 코드 작성
- 기존 코드 수정
- 리뷰 반영
- 버그 수정
- 리팩터링 (승인된 범위)

CODEX는 설계 문서와 구현 가이드를 기준으로 작업합니다.

세부 규칙은 `AGENTS.md`를 참조합니다.

---

### CLAUDE

CLAUDE는 코드 품질과 설계 일관성을 검증합니다.

주요 역할

- 코드 리뷰
- 설계 검증
- 성능 검토
- 테스트 검토
- 개선 사항 제안

CLAUDE는 직접 구현하지 않고 리뷰와 개선 제안에 집중합니다.

세부 규칙은 `docs/rules/review-agent-rule.md`를 참조합니다.

---

## 개발 흐름

작업은 아래 순서를 따릅니다.

1. 요구사항 분석 (CLAUDE)
2. 기능 명세 및 설계 (CLAUDE)
3. 사용자 승인
4. 구현 (CODEX)
5. 코드 리뷰 (CLAUDE)
6. 리뷰 반영 (CODEX)
7. 테스트 및 검증 (CODEX)
8. 문서화 (CLAUDE)
9. PR 작성 (CLAUDE)

---

## 산출물

프로젝트에 따라 아래 문서를 작성합니다.

- 기능 명세
- 아키텍처 문서
- API 문서
- 기술 의사결정 문서
- Work Log
- Pull Request

문서의 위치와 형식은 프로젝트 규칙을 따릅니다.

---

## Agent별 금지 사항

### CLAUDE

- 명세 없이 구현하지 않습니다.
- 승인 없이 구조를 변경하지 않습니다.
- 프로젝트 범위를 벗어난 기능을 추가하지 않습니다.

### CODEX

- 요구사항을 임의로 해석하지 않습니다.
- 승인 없이 아키텍처를 변경하지 않습니다.
- 명세 없이 구조를 변경하지 않습니다.
- 승인되지 않은 라이브러리를 추가하지 않습니다.

### CLAUDE

- 직접 구현하지 않습니다.
- 요구사항을 변경하지 않습니다.
- 사용자 승인 없이 설계를 변경하지 않습니다.

---

## 사용자 승인

최종 기술 선택과 구조 결정은 사용자에게 있습니다.

Agent는 제안과 구현을 수행하며,
사용자의 승인 없이 중요한 결정을 내리지 않습니다.

---

## Agent 간 인수인계

각 Agent는 다음 Agent가 작업을 이어갈 수 있도록
필요한 산출물과 문서를 제공합니다.

다음 Agent는 이전 Agent의 산출물을 확인한 뒤 작업을 진행합니다.
