## 1. 1차 PoC 목적

1차 PoC의 목적은 높은 정확도를 만드는 것이 아니다.

핵심은 다음 전체 흐름이 실제 데이터에서 정상적으로 동작하는지 검증하는 것이다.

```
AI-Hub 원본 데이터
→ 이미지·JSON 구조 분석
→ Polygon 좌표 추출
→ Bounding Box 변환
→ YOLO Detection 데이터셋 생성
→ 모델 학습
→ 새로운 이미지 추론
→ 자동 라벨 파일 생성
→ 결과 시각화 및 평가
```

따라서 1차 PoC에서는 범위를 작게 제한한다.

---

# 2. 1차 PoC 대상 데이터

## 2.1 검사 유형

**RT 데이터를 우선 사용한다.**

```
검사 유형: RT
```

선택 이유:

- 내부 결함이 이미지에 비교적 명확하게 나타난다.
- 현재 확보한 예제 JSON과 이미지가 RT 데이터 중심이다.
- Polygon 라벨을 활용해 Detection과 Segmentation으로 확장하기 좋다.
- 초기 데이터 구조 분석 범위를 줄일 수 있다.

VT는 1차 PoC 완료 후 확장한다.

---

## 2.2 소재

**AL 소재를 우선 사용한다.**

```
소재: AL
```

선택 이유:

- 현재 확인한 예제 데이터의 소재가 AL이다.
- 하나의 소재로 제한하면 촬영 특성과 결함 표현 차이를 줄일 수 있다.
- 소재별 특징 차이보다 데이터 처리 파이프라인 검증에 집중할 수 있다.

다른 소재는 1차 PoC 이후 별도 실험으로 확장한다.

---

# 3. 대상 클래스

## 3.1 초기 클래스 후보

첫 실험은 정상과 결함 클래스 2개를 사용한다.

```
정상
기공
슬래그 혼입
```

영문 클래스 예시:

```
normal
porosity
slag_inclusion
```

다만 Object Detection 학습에서는 `normal`을 객체 클래스로 만들지 않는다.

```
정상 이미지
→ 객체 라벨이 없는 이미지

불량 이미지
→ porosity 또는 slag_inclusion 객체 존재
```

따라서 실제 Detection 클래스는 다음 두 개다.

```
0: porosity
1: slag_inclusion
```

---

## 3.2 클래스 선택 이유

### 기공

- 비교적 형태가 명확한 결함일 가능성이 높다.
- 작은 객체 탐지 문제를 확인할 수 있다.
- 같은 이미지에 여러 개 존재할 수 있어 다중 객체 처리를 검증할 수 있다.

### 슬래그 혼입

- 기공과 형태가 다를 가능성이 있다.
- 클래스 구분 능력을 확인할 수 있다.
- 불규칙한 Polygon을 Bounding Box로 변환했을 때 정보 손실을 확인할 수 있다.

---

## 3.3 클래스 선정 전 확인 사항

실제 데이터 통계를 확인한 뒤 다음 조건을 만족해야 한다.

- 클래스별 이미지 수가 너무 적지 않은가
- 클래스별 객체 수가 충분한가
- 클래스 이름이 JSON에 일관되게 저장되어 있는가
- 한글명과 영문명 매핑이 가능한가
- 동일 결함의 표기 방식이 여러 개 존재하지 않는가

예를 들어 다음처럼 이름이 혼재할 수 있다.

```
슬래그혼입
슬래그 혼입
slag inclusion
slag_inclusion
```

이 경우 하나의 표준 클래스명으로 통합해야 한다.

# 4. 데이터 수

## 4.1 1차 목표 수량

처음부터 전체 데이터를 사용하지 않는다.

초기 목표:

```
정상 이미지: 100장
기공 이미지: 100장
슬래그 혼입 이미지: 100장

총 이미지: 약 300장
```

단, 이미지 한 장에 여러 결함이 있을 수 있으므로 이미지 수와 객체 수를 함께 기록한다.

권장 객체 수:

```
기공 객체: 최소 150개 이상
슬래그 혼입 객체: 최소 150개 이상
```

---

## 4.2 최소 실행 범위

데이터 구조와 코드 검증 단계에서는 더 적게 시작할 수 있다.

```
구조 검증용: 10~20장
변환 검증용: 30~50장
첫 학습용: 약 300장
```

진행 순서는 다음과 같다.

```
10~20장
→ JSON 구조와 좌표 추출 확인

30~50장
→ 변환·시각화·검증

약 300장
→ 첫 Baseline 학습
```

---

## 4.3 데이터 부족 시 처리

특정 클래스가 부족하면 다음 순서로 대응한다.

```
1. 클래스별 실제 데이터 수 재확인
2. 다른 소재 포함 여부 검토
3. 유사 결함 클래스 대체 검토
4. 클래스 수를 1개로 축소
5. 전체 RT 데이터로 확장
```

1차 PoC를 위해 억지로 균형을 맞추는 증강은 아직 하지 않는다.

# 5. 라벨 표현 방식

## 5.1 원본 라벨

AI-Hub 원본 데이터의 Polygon을 기준 정답으로 사용한다.

```
원본 Ground Truth
→ Polygon
```

## 5.2 1차 학습 라벨

1차 PoC 모델은 Bounding Box 기반 Detection으로 진행한다.

```
Polygon
→ Bounding Box 변환
→ YOLO Detection
```

## 5.3 Detection 우선 이유

- 전체 파이프라인을 빠르게 검증할 수 있다.
- 좌표 변환과 오류 확인이 비교적 단순하다.
- 학습과 추론 속도가 Segmentation보다 가볍다.
- 자동 라벨 파일 생성 구조를 이해하기 쉽다.
- MVP의 첫 화면에서 Box 검수 기능을 먼저 만들 수 있다.

---

## 5.4 Segmentation 처리

Segmentation은 1차 PoC의 필수 범위에서 제외한다.

다만 원본 Polygon을 버리지 않고 유지한다.

```
원본 Polygon
→ 원본 Ground Truth 보존

변환 Bounding Box
→ 1차 Detection 학습에 사용
```

이후 같은 데이터로 YOLO Segmentation을 수행할 수 있어야 한다.

---

# 6. 데이터 분할

기본 분할 비율은 다음으로 한다.

```
Train: 70%
Validation: 15%
Test: 15%
```

300장 기준 예시:

```
Train: 210장
Validation: 45장
Test: 45장
```

분할 조건:

- 클래스별 비율을 최대한 유지한다.
- 같은 이미지가 여러 분할에 들어가지 않는다.
- 동일 원본에서 만들어진 복제·변형 이미지는 같은 분할에 넣는다.
- 정상 이미지가 각 분할에 포함되도록 한다.
- Random Seed를 고정한다.

초기 Seed:

```
42
```

# 7. 첫 번째 모델 유형

1차 PoC에서는 사전 학습된 소형 YOLO Detection 모델을 사용한다.

모델 선택 기준:

- 설치와 실행이 간단함
- 학습 예제가 충분함
- CPU 또는 보급형 GPU에서도 실행 가능
- Bounding Box Detection 지원
- 추론 결과를 Python에서 쉽게 읽을 수 있음
- 추후 Segmentation 모델로 확장 가능

정확한 YOLO 버전과 모델 크기는 다음 항목인 **C-8. 기준 모델 및 실험 조건**에서 확정한다.

# 8. 1차 PoC에서 검증할 핵심 질문

## 8.1 데이터 질문

- AI-Hub 이미지와 JSON을 정확히 연결할 수 있는가?
- JSON에서 결함 클래스와 Polygon 좌표를 안정적으로 추출할 수 있는가?
- 잘못된 좌표와 누락 데이터를 자동으로 찾을 수 있는가?
- 클래스 이름을 일관된 값으로 정규화할 수 있는가?

## 8.2 변환 질문

- Polygon을 Bounding Box로 정확히 변환할 수 있는가?
- 변환된 YOLO Detection 좌표가 원본 결함 위치와 일치하는가?
- 정상 이미지를 객체가 없는 학습 데이터로 처리할 수 있는가?
- 변환 전후 객체 수와 클래스가 동일하게 유지되는가?

## 8.3 모델 질문

- 소규모 데이터로 YOLO 학습이 정상적으로 실행되는가?
- 새로운 이미지에서 결함 클래스와 위치를 예측할 수 있는가?
- 모델의 예측 결과를 Python에서 추출할 수 있는가?
- Prediction을 YOLO TXT 형식으로 저장할 수 있는가?

## 8.4 평가 질문

- 클래스별 Precision과 Recall을 확인할 수 있는가?
- 오탐과 미탐을 이미지 단위로 분류할 수 있는가?
- 작은 결함에서 미탐이 증가하는가?
- Polygon을 Box로 변환한 것이 성능이나 검수에 어떤 영향을 주는가?

## 8.5 오토라벨링 질문

- 예측 결과를 원본 이미지 위에 표시할 수 있는가?
- 자동 생성된 라벨을 CVAT로 가져올 수 있는가?
- 사람이 자동 라벨을 수정할 수 있는가?
- 수동으로 처음부터 라벨링하는 것보다 수정 작업이 줄어드는가?

- 모든 결함 클래스 학습

- 실시간 추론
- Backend API
- Frontend 화면
- 사용자 계정과 권한
- 데이터베이스 저장
- 자동 재학습
- 모델 배포 및 운영
- 하이퍼파라미터 최적화
- 성능 목표 수치 확정

```

2차
RT + AL + 전체 결함 클래스 + Detection

RT + 여러 소재 + Detection
```

각 단계는 이전 단계의 데이터 변환과 학습 흐름이 안정적으로 동작한 뒤 진행한다.

# 12. 완료 조건

현재 항목을 완료하려면 실제 데이터 통계로 다음 세 가지만 확인해야 한다.

- `( )` RT·AL 데이터에서 `porosity`와 `slag_inclusion`의 이미지 및 객체 수가 충분한지 확인
- `( )` 실제 JSON 클래스명이 어떤 값으로 저장되어 있는지 확인
- `( )` 정상 이미지 100장과 각 결함 이미지 100장 수준으로 선별 가능한지 확인
