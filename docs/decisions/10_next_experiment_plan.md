## Baseline의 가장 큰 문제

**작은(그리고 저대비) 결함에 대한 Recall 부족.** Test 58개 결함 중 48개(83%)를 놓쳤고, 그중에서도 특히 작은 객체를 더 놓친다.

## 근거

- 전체 Recall 0.188, 미탐 48/58건(83%) — `reports/evaluation/model_performance.csv`, `error_type_counts.csv`
- 객체 크기별 Recall: Small(33개) 0.121 < Medium(24개) 0.167 — `reports/evaluation/object_size_performance.csv`
- 클래스별 Recall: porosity(작은 객체 위주) 0.143 < slag_inclusion(중간 크기 위주) 0.233 — 크기 축과 클래스 축 양쪽에서 같은 방향의 신호(`experiment.md` 11.3~11.4절)
- 미탐 대표 사례 육안 검토 결과, 검토한 사례 전부 GT 박스 안의 명암 대비가 매우 낮아 사람 눈으로도 식별이 어려운 수준이었음(`docs/reports/08_error_analysis.md`)
- Confidence 분포 자체가 낮게 형성돼 있음(Threshold 0.50 이상에서는 실제 배포 기준 탐지 0건, 작업22) — 모델이 결함의 특징을 약하게만 포착하고 있다는 정황과 일치

## 원인 가설

원본 이미지가 학습·추론 시 `imgsz=640`으로 리사이즈되며, 작은 결함의 픽셀 정보(대비·경계 디테일)가 추가로 손실되어 이미 저대비인 결함을 모델이 인식하기 더 어려워진다. Train 데이터가 209장으로 적다는 근본 제약과 별개로, **입력 해상도 부족이 작은/저대비 결함 인식을 추가로 어렵게 만드는 독립적 요인**일 가능성이 크다.

## 변경할 변수 (한 개)

`imgsz: 640 → 960`

## 고정할 조건

- 데이터셋: `data/processed/dataset_v1/`(동일 split, seed=42) — 재분할하지 않음
- 모델: `yolo26n.pt`(사전 학습 가중치, 동일 크기 n)
- 학습 설정: epochs=50, patience=15, batch=-1(auto), optimizer="auto", device="cpu", cache=True, deterministic=True — Baseline과 완전히 동일
- 증강 설정: library default(변경 없음)
- 평가 조건: conf=0.25, NMS IoU=0.70, 매칭 IoU=0.5 — 작업22~24와 동일 기준으로 비교 가능하게 유지

## 성공 판단 기준

- **주 지표**: Small 객체 Recall이 Baseline(0.121) 대비 뚜렷이 개선(목표: 0.20 이상, 상대적으로 약 65% 개선)
- **가드레일 1**: 전체 mAP50-95가 Baseline(0.043)보다 낮아지지 않을 것(해상도를 올렸는데 다른 지표가 희생되면 순개선이라 보기 어려움)
- **가드레일 2**: CPU 환경에서 총 학습 시간이 Baseline(약 21분) 대비 과도하게 늘지 않을 것(참고 기준: 3배, 약 63분 이내) — 이 조건을 못 지키면 GPU 확보 여부를 먼저 논의해야 함
- 위 기준을 충족하면 EXP-P1-DET-002를 채택하고, 미달하면 "입력 해상도"가 주된 원인이 아니었다고 결론 내리고 후속 우선순위 2번(Box 위치 부정확 개선)으로 넘어간다

## 후속 실험 우선순위

1. **imgsz 640→960**(이번 실험, EXP-P1-DET-002) — 작은/저대비 결함 Recall 개선
2. **Box 회귀 손실 가중치 조정 또는 학습 연장(patience 상향)** — 위치 오류(예측 박스가 GT보다 작게 나오는 경향) 개선, mAP50-95 향상 목적
3. **Hard Negative Mining** — 오탐 3건이 발생한 위치를 추가 학습 데이터로 보강(다만 오탐 자체가 이미 소수라 우선순위는 낮음)
4. **Polygon→Box 변환 방식 재검토(배경 최소화)** — 변환 파이프라인 자체를 건드리는 더 큰 변경이라, 위 실험들로 원인을 좁힌 뒤 장기 과제로 검토
