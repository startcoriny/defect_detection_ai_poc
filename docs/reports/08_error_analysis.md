# 오탐·미탐 분석 보고서

- 대상 실험: EXP-P1-DET-001 (RT_AL_YOLO26N_640_Baseline)
- 평가 조건: Confidence 0.25, NMS IoU 0.70, imgsz 640, 매칭(TP 판정) IoU 0.5, Test 46장(실제 결함 58개)
- 근거 산출물: `reports/evaluation/{error_cases.csv, error_type_counts.csv}`, `errors/{false_positive, false_negative, wrong_class, localization_error}/`
- 매칭 방법: `src/evaluation/collect_error_cases.py`가 4단계로 분류한다 — ① 같은 클래스+IoU≥0.5(정답, 분석 대상 아님) → ② 남은 것 중 클래스가 달라도 IoU≥0.5(**클래스 오류**) → ③ 남은 것 중 같은 클래스이고 0.1≤IoU<0.5(**위치 오류**) → ④ 그래도 남은 예측은 **오탐**, 남은 정답은 **미탐**. 위치 오류의 하한 0.1은 "전혀 안 겹침"과 "애매하게 겹침"을 구분하기 위해 이번에 정한 값이며 문서에 명시된 기준은 아니다.

## 전체 집계

| 오류 유형 | porosity | slag_inclusion | 합계 |
| --- | ---: | ---: | ---: |
| 미탐(false_negative) | 23 | 25 | 48 |
| 오탐(false_positive) | 1 | 2 | 3 |
| 위치 오류(localization_error) | 2 | 0 | 2 |
| 클래스 오류(wrong_class) | 0 | 0 | 0 |

합계 검증: TP(작업23 기준 single-label 매칭 8건) + 위치 오류(2) + 클래스 오류(0) + 미탐(48) = 58 = Test 전체 정답 객체 수와 정확히 일치. 예측 쪽도 TP(8) + 위치 오류(2) + 클래스 오류(0) + 오탐(3) = 13 = 실제 배포(single-label) 기준 전체 예측 수와 정확히 일치(교차 검증 완료).

## 오탐(False Positive) 유형 분석 — 3건 전부 검토

| 사례 | 예측 | Confidence | 실제 이 자리에 있던 것 |
| --- | --- | ---: | --- |
| `RT_AL_02_14488786_001` | slag_inclusion | 0.289 | porosity(GT, IoU 부족으로 별도 미탐 처리) |
| `RT_AL_02_14489318_001` | slag_inclusion | 0.271 | porosity(GT, 위와 동일 패턴) |
| `RT_AL_05_14492380_001` | porosity | 0.250 | 배경(순수 오탐, 이미지 반대편에 큰 slag_inclusion 결함을 놓침) |

**분류**:
- **낮은 Confidence**: 3건 전부 0.25~0.29로 임계값(0.25) 바로 위에 몰려 있다. 모델이 확신을 갖고 낸 오탐이 아니라, "애매한 걸 억지로 걸러낸" 경계선 케이스에 가깝다.
- **잘못된 클래스(성격은 다르지만 관련 있음)**: 위 2건(`14488786`, `14489318`)은 실제로는 그 자리에 porosity 결함이 있었는데 모델이 slag_inclusion으로 잘못 예측하면서 동시에 박스 위치도 부정확(IoU<0.5)했던, "클래스 오류"와 "미탐"이 겹친 복합 실패다(그래서 CSV에는 같은 이미지에 오탐 1건 + 미탐 1건으로 따로 기록됨 — 로직상 자연스러운 결과이며 버그 아님).
- **정상 패턴 오인**: `RT_AL_05_14492380`은 이미지 안에 실제로 크고 뚜렷한 slag_inclusion 결함이 있는데(중앙의 어두운 얼룩) 그건 완전히 놓치고, 반대쪽 구석의 깨끗한 영역에 작은 porosity를 잘못 예측했다. 모델의 주의가 실제 결함의 시각적 특징과 잘 맞물리지 않는다는 신호다.
- **중복 예측**: 0건(`duplicate_of_tp` 전부 False) — NMS가 같은 객체를 여러 번 잡는 문제는 없었다.
- **지나치게 큰 Box**: 0건 — 3건 모두 `box_area_ratio`가 이미지의 0.1~3% 수준으로 작다. 오탐이 "과도하게 큰 박스"에서 온 게 아니다.
- **Ground Truth 오류 가능성**: 낮음 — 3건 모두 GT 라벨 자체는 이미지와 맞아떨어졌고(작업15에서 검증 완료), GT가 잘못된 것으로 보이는 사례는 없었다.

## 미탐(False Negative) 유형 분석 — 48건 중 대표 사례 검토

전수 검토는 어려워 클래스·크기별로 대표 사례를 육안 확인했다(`RT_AL_02_14488461_001`(porosity, Medium), `RT_AL_05_14489815_001`(slag_inclusion, Small) 등).

- **흐릿한 결함**: 검토한 사례 전부 GT 박스 안의 명암 대비가 매우 낮다 — 사람 눈으로도 박스 표시가 없으면 결함인지 알아보기 어려운 수준이다. 이번 Baseline의 미탐 48건 중 다수가 이 유형으로 보인다.
- **작은 결함**: 작업23에서 이미 정량적으로 확인됨(Small Recall 0.121 < Medium 0.167). 미탐 48건 중 Small 버킷 비중이 가장 크다.
- **경계 결함**: 48건 중 3건(`RT_AL_05_14491968_002`, `RT_AL_05_14492576_002`, `RT_AL_05_14492843_002`)이 이미지 가장자리 5% 이내에 위치 — 소수지만 존재한다.
- **클래스 혼동**: 위 오탐 분석에서 다룬 2건(porosity GT가 slag_inclusion으로 오분류되며 동시에 미탐 처리된 경우)이 여기 해당한다.
- **데이터 부족**: Train 209장(porosity 185개 객체, slag_inclusion 147개 객체)은 Object Detection 학습치고 적은 편이다. 클래스별 성능 격차(작업23 11.3절)가 학습 데이터 양보다 객체 크기와 더 강하게 연관돼 보이긴 하지만, 전체적인 미탐률(58건 중 48건, 83%)이 높은 근본 배경으로는 데이터 절대량 부족이 유력하다.
- **이미지 축소 영향**: 원본 이미지가 imgsz=640으로 리사이즈되며 작은 결함의 픽셀 정보가 줄어드는 영향은 배제할 수 없으나, 이번 검토 대상 이미지들에서 리사이즈 전후를 직접 비교하지는 않았다 — 작업25에서 imgsz 확대 실험으로 검증할 사안이다.
- **라벨 오류 가능성**: 검토한 사례들의 GT 위치는 모두 타당해 보였다(박스 안에 실제로 흐릿한 얼룩이 존재). 라벨 오류로 의심되는 사례는 발견하지 못했다.

## 위치 오류(Localization Error) — 2건 전부 검토

- `RT_AL_02_14488001_001`(porosity, Confidence 0.363): 예측 박스가 GT 박스보다 뚜렷하게 작다(GT 안에 완전히 포함되는 축소된 박스). 클래스와 대략적 위치는 맞지만 결함의 실제 크기를 과소평가했다.
- 나머지 1건도 동일한 패턴(예측 박스 축소).

이 2건은 작업23에서 확인한 "mAP50(0.175) 대비 mAP50-95(0.043)가 훨씬 낮다"는 결과를 시각적으로 뒷받침한다 — 모델이 결함의 대략적 존재·위치는 인식하지만, 박스 경계를 정밀하게 그리지 못한다.

## 클래스 오류(Wrong Class, 엄격 정의: IoU≥0.5 + 다른 클래스) — 0건

이번 조건(conf=0.25, single-label)에서는 발생하지 않았다. 다만 위 오탐 분석에서 다룬 2건은 "클래스도 틀리고 위치도 부정확한" 복합 실패라, 엄격한 정의로는 클래스 오류에 집계되지 않지만 실질적으로는 클래스 혼동의 영향이 있다.

## 원인별 분류 (데이터 · 라벨 · 모델 관점)

- **데이터 관점**: Train 209장이라는 절대적 데이터 부족, 특히 작은 객체(porosity 위주) 표본 부족이 가장 근본적인 원인 후보다.
- **라벨 관점**: 이번에 검토한 사례들에서 라벨 자체의 오류는 발견되지 않았다(작업15의 검증 결과와 일치). 라벨 품질은 문제의 주된 원인이 아닌 것으로 보인다.
- **모델 관점**: (1) 박스 회귀 정밀도가 낮다(위치 오류 2건, mAP50 vs mAP50-95 격차), (2) 저대비 결함에 대한 특징 추출력이 부족하다(미탐 대부분의 공통 패턴), (3) 오탐 3건 모두 임계값 바로 위의 낮은 확신도라 전반적으로 모델의 확신도 자체가 낮게 형성돼 있다(작업22에서 이미 확인한 "Confidence 0.50 이상 예측이 거의 없다"는 관찰과 일치).

## 개선 후보

1. **imgsz 확대(640→960)**: 작은 결함·저대비 결함의 정보 손실을 줄여 미탐(특히 Small 버킷)을 개선할 가능성. (작업23의 크기별 Recall 격차, 이번 미탐 사례의 저대비 패턴 둘 다 이 방향을 뒷받침)
2. **박스 회귀 손실 가중치 조정 또는 학습 연장**: 위치 오류 사례(박스가 GT보다 작게 나옴)를 줄이기 위해 box loss 비중을 높이거나 학습을 더 진행해볼 수 있다.
3. **Hard Negative Mining**: 오탐이 발생한 위치(경계선 Confidence 영역)를 추가 학습 데이터로 보강.
4. **클래스별 Threshold 분리**: 오탐 3건이 전부 Confidence 0.25~0.29에 몰려 있어, Threshold를 아주 조금만 올려도(예: 0.30) 이번에 관찰된 오탐 3건은 걸러질 가능성이 있다(단, 미탐이 이미 많은 상황이라 Recall을 더 깎는 트레이드오프가 있음 — 작업22의 Threshold 비교 결과 참고).
